## Model Router: global workflow

This is the US$20 allowance profile. It applies the quota-conserving override after the base routing decision. This is an allowance strategy, not an official OpenAI subscription label.

For every new substantive user task, use the installed `model-router-20` skill before doing any work. A substantive task asks to analyze, research, create, modify, review, diagnose, or otherwise perform work. Meta questions and short confirmations are not substantive tasks.

- Except for the standalone maintenance commands below, if the task does not begin with a valid confirmation token, do not execute it, use tools, browse, edit files, make a plan, or delegate. Return the skill's routing recommendation (three lines, plus the verified update exception below) and wait for confirmation. Valid tokens are `执行` or `按推荐执行` for Chinese, and the standalone word `go` for English.
- When the user sends a valid confirmation token after that recommendation, perform the immediately preceding task using the model selected by the user. Do not claim that the selection was verified or switched automatically.
- Follow the installed skill's output-language contract exactly. Keep model choice and reasoning effort separate. Do not recommend or change speed settings. Never use `Standard` as a reasoning-effort label.
- `$model-router-20` remains an optional explicit fallback when the user wants to force a routing-only turn.
- Reassess the whole request; do not carry forward Luna/Terra from an earlier turn or classify only the easiest first step. Luna requires ALL: one narrow explicit outcome, no investigation/design or coupled state/data-flow changes, and cheap local verification. Terra requires clear sources, a bounded writing/visual/computer-use/known-fix outcome and concrete verification, with no unresolved repeated bug, coupled lifecycle/role/permission/data-flow change, conflicting evidence or costly hidden failure. If these conditions are not established, start at Sol Medium; use High for coupling/ambiguity and assess Astra for demanding integration. Apply allowance overrides once after the base route.
- Return one recommendation in three lines: Chinese uses `模型：…；推理强度：…`, `原因：…`, `操作：…执行…`; English uses `Model: …; reasoning effort: …`, `Reason: …`, `Action: …go…`. Give a task-specific reason, not an execution plan. Only verified local hook context may add one fourth update-notice line in the same language. Never check updates with model tools before routing or append notices on execution/confirmation turns.
- Standalone `更新路由器` / `update router` and `检查路由器更新` / `check router update` are router maintenance, exempt from the routing gate. Read the installed skill's `references/updating.md`, use its maintenance script, and preserve the active profile. These commands do not confirm or execute a pending task. A notice is not update authorization; do not bypass hook trust.
