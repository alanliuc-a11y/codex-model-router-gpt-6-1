# 更新提醒：安装、测试与恢复

## 验证范围

仓库包含离线集成测试，覆盖两个档位、缓存、语言分离、更新授权、保留其他配置、拒绝损坏下载及安装失败回滚。这些测试验证脚本，不证明桌面客户端已运行检查脚本，也不证明模型每次输出正确。请用真实客户端完成下方步骤。

## 安装

1. 按[中文说明](../README.zh-CN.md)安装一个 1.3.0 档位。没有提醒功能的旧版本必须先升级一次；1.2.1 用户可使用已有更新器。
2. 使用本机可用的 Python 3.10 或更高版本。在已安装的技能目录内，先运行全局路由脚本，再运行 `python scripts/router-update.py enable-hooks`；其他系统通常使用 `python3`。
3. 在客户端支持的脚本审核入口，检查并信任两个新配置。命令行客户端使用 `/hooks`。必要时重启或新建会话；桌面客户端不支持时，保留普通路由并手动检查，不能把写入配置当作已经运行。[官方脚本机制](https://learn.chatgpt.com/docs/hooks)
4. 检查在提交任务时触发，不会在关闭 Codex 后继续监听。前台只读缓存，后台每二十四小时最多联网一次，失败也会缓存。手动检查可立即刷新；首次检查可能来不及影响当前推荐。

## 真实客户端测试

1. **正常任务：**输入明确的会议记录整理任务，应得到三行模型推荐。已经是最新版时不应出现更新提醒。
2. **确认任务：**选好模型后单独发送「执行」，应继续原任务，不应再次推荐或添加更新提醒。
3. **手动检查：**单独发送「检查路由器更新」，应报告核实的版本或检查不可用；检查失败不能说“已经是最新版”。
4. **将来发布新版：**等待下一次允许的后台检查，或手动刷新，再输入一个新任务。推荐下方最多增加一行中文更新提醒。英文流程使用对应英文说明测试。
5. **更新技能：**单独发送「更新路由器」，应保留安装档位，报告核对过的新版本及备份位置；不会执行待确认任务。配置改变后如有要求，请重新审核；新一轮或新会话加载新版。
6. **断网：**断网后仍能正常路由。过去核实的新版本提醒最多保留七天；检查不可用不能当作没有新版。
7. **关闭提醒：**运行 `python scripts/router-update.py disable-hooks` 并重新加载客户端，普通路由应继续，提醒停止，其他检查脚本不受影响。

不要为演示制造公开假版本，也不要往真实配置里伪造新版。离线测试会在临时目录中模拟未来发布版本，不改用户配置。

## 自动测试

在仓库目录运行：

```sh
python -m unittest discover -s tests -v
```

测试只创建并清理自身位于 `tests` 内的临时文件夹，不联网。准备发布时运行 `python scripts/build-manifests.py` 更新两个档位的校验清单。仓库的自动检查覆盖三种操作系统；实际检查通过才是证据，配置文件存在不代表已经通过。

## 恢复与限制

只有 GitHub 正式发布版本才触发提醒，仅提交代码不会触发。文本文件校验允许不同系统的换行符；它能检查损坏及打包不一致，但不是独立于仓库的安全签名。

每次升级保留 `<CODEX_HOME>/skill-backups/router-update-.../`。其中 `previous` 是完整旧技能；原来存在的 `AGENTS.md` 和 `hooks.json` 会保存原始配置字节；失败时可能还有 `failed`。安装中可捕获的失败会自动恢复；系统突然退出或恢复时也无法写文件的情况可能需要人工处理。

手动恢复前先停止更新操作并保留新工作，再让 Codex 只恢复本次事务中的旧档位及对应配置，不要删除整个技能目录或无关规则。恢复后检查脚本信任状态。备份不会自动删除。

修改过技能文件或 Git 克隆安装的目录不会被更新器覆盖，应在保留改动的前提下手动升级。配置中记录的运行程序路径失效时，用可用程序重新启用提醒。原路由禁用脚本只管路由；完整卸载前应先关闭提醒及路由两者。
